## High-level view

The generator metadata change is a single-line edit that replaces the name, description, and rationale fields for SE_007, aligning them with the signal's actual backward-looking semantics. The `data_limitations` field now explicitly notes that the function name `pre_holiday_bullishness` is retained for API compatibility while the behavior is post-holiday detection.

The four regression tests construct DatetimeIndex fixtures with known calendar gaps and assert the signal fires only on the correct bar (the day after a >3-day gap). They cover the positive case, the negative case (pre-holiday bar must not fire), the zero case (normal business days), and the multi-gap case. The threshold boundary (gap == 3 for a standard weekend does not fire, gap > 3 does) is implicitly tested by the normal-weekday test using `pd.bdate_range`.

The audit document's SE_007 row and Section 3.1 both reference the corrected "Post-Holiday Bullishness" name and note the generator metadata update, closing the documentation-code mismatch flagged in v1.
