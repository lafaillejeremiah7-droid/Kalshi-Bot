# Look-ahead bias fix and signal audit document

This change fixes a confirmed look-ahead bias in `pre_holiday_bullishness` (SE_007) and adds a 497-line audit document cataloging all 103 signals in the research pipeline. The original signal used `.diff().shift(-1).dt.days` to peek at the *next* trading day's date gap, which is future information unavailable at signal-generation time. The fix replaces this with `.diff().dt.days`, detecting post-holiday sessions by looking backward at the gap from the previous day. A comprehensive audit document (`results/signal_audit.md`) is produced covering look-ahead verification, data labeling, chronological enforcement, FDR correction, and optimization gating for all signals.

Watch for: the hypothesis metadata in `generator.py` still describes SE_007 as "Day *before* multi-day market closure" with the name "Pre-Holiday Bullishness," but the signal now fires on the *first day back* after a break (confirmed, lines 439 of generator.py vs lines 748-763 of signals.py). No unit test covers this signal's new behavior (confirmed).

**Verdict**: NEEDS_CHANGES

---

## High-level view

The signal fix itself is sound: `.diff().shift(-1)` was unambiguous look-ahead, and `.diff()` without the negative shift correctly computes the calendar-day gap between today and the previous trading day. The economic rationale (short covering, optimism) is plausibly redirected from "pre-holiday" to "post-holiday," though the hypothesis is now testing a subtly different calendar anomaly than the one originally stated. The generator metadata (name, description, rationale) was not updated to match, creating a documentation-code mismatch that will mislead researchers reading the catalog.

The audit document covers all nine verification axes requested. Its one structural gap is that it reports SE_007 as "FIXED" without noting the stale metadata in `generator.py`, implying alignment that doesn't exist.

## Signal fix: pre_holiday_bullishness becomes post-holiday detection

The original code:

```python
day_diff = pd.Series(df.index, index=df.index).diff().shift(-1).dt.days
pre_holiday = day_diff > 3
```

This asks "is *tomorrow's* date more than 3 days away?" — classic look-ahead. The new code:

```python
day_diff = pd.Series(df.index, index=df.index).diff().dt.days
post_holiday = day_diff > 3
```

This asks "was the gap between *yesterday* and *today* more than 3 days?" — purely backward-looking.

This changes what the signal tests. Pre-holiday bullishness and post-holiday bullishness are distinct calendar anomalies in the literature. The original hypothesis (SE_007) posited short-covering pressure *before* a break. The new signal detects the first session *after* a break, where the dominant mechanism is different (pent-up order flow, optimism bias on return). The hypothesis metadata in `generator.py` line 439 still reads:

> name="Pre-Holiday Bullishness"  
> description="Day before multi-day market closure tends to be positive."  
> economic_rationale="Short sellers cover before holidays; optimism bias..."

A researcher relying on the catalog to understand what SE_007 tests will get the wrong mental model. The name should become something like "Post-Holiday Bullishness" and the description/rationale should reference the return-from-break mechanism.

## Missing test coverage for the fixed signal

No file in `tests/` references `pre_holiday_bullishness`, `SE_007`, or `post_holiday`. The fix changed the signal's behavior in a non-trivial way (it fires on entirely different dates), and there's no regression guard. A minimal test would construct a 10-bar DataFrame with a DatetimeIndex where one pair of consecutive dates has a 4-day gap, then assert:
- The signal is 1.0 on the day *after* the gap (the post-holiday bar)
- The signal is 0.0 on the day *before* the gap

This would have caught the original bug and will prevent regressions if the function is refactored again.

## Audit document: SE_007 metadata gap

The SE_007 row in the audit's Section 2.5 says "FIXED: Was using .shift(-1). Now backward-looking" but still carries the old name "Pre-Holiday Bullishness" without noting that the generator metadata is stale. Since this document is meant to be the authoritative signal catalog, it should either flag the discrepancy or be updated after the generator metadata is corrected.
